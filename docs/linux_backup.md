Создание полной резервной копии работающей системы Debian через SSH можно выполнить несколькими способами. Выбор метода зависит от того, что вам нужно: **побитовый образ всего диска** (для восстановления «один в один») или **копия всех файлов** (для переноса системы или восстановления данных).

Вот три лучших способа.

---

### Важное предупреждение
Создание резервной копии **работающей** (смонтированной) системы может привести к несогласованности данных (например, если файл меняется в момент чтения).
*   Для идеального бэкапа лучше загрузить сервер в **Rescue Mode** (режим восстановления).
*   Если это невозможно, остановите все важные службы (MySQL, Docker, Apache/Nginx) перед началом.

---

### Способ 1: `dd` (Полный побитовый образ диска)
Этот метод создает точную копию жесткого диска или раздела, включая таблицу разделов, загрузчик (MBR/UEFI) и пустое пространство.

**Где выполнять:** На локальном компьютере (куда сохраняем бэкап).
**Требования:** Достаточно места на локальном диске (равно размеру удаленного диска, даже если он пустой, но сжатие поможет).

**Команда:**
```bash
ssh root@IP_УДАЛЕННОГО_СЕРВЕРА "dd if=/dev/sda bs=4M status=progress | gzip -1 -" | dd of=debian_backup.img.gz
```

*   `ssh root@...` — подключаемся к серверу.
*   `dd if=/dev/sda` — читаем весь диск `sda` (проверьте имя диска через `lsblk`, это может быть `vda` или `nvme0n1`).
*   `gzip -1 -` — сжимаем данные на лету (быстрое сжатие), чтобы меньше передавать по сети.
*   `|` (pipe) — передаем данные через SSH туннель на ваш компьютер.
*   `dd of=debian_backup.img.gz` — записываем результат в файл на вашем компьютере.

**Как восстановить:**
Загрузиться с LiveUSB и выполнить команду в обратном порядке:
```bash
dd if=debian_backup.img.gz | gunzip -c | ssh root@IP_СЕРВЕРА "dd of=/dev/sda bs=4M"
```

### Способ 2: `rsync` (Копирование файловой системы) — Рекомендуемый
Это самый гибкий способ. Он копирует только файлы, сохраняя права доступа, владельцев и время. Идеально подходит для миграции на другой сервер или VPS.

**Где выполнять:** На локальном компьютере (Linux/macOS) или на сервере бэкапов.

**Команда:**
```bash
rsync -aAXv --delete --numeric-ids --info=progress2 \
  --exclude={"/dev/*","/proc/*","/sys/*","/tmp/*","/run/*","/mnt/*","/media/*","/lost+found"} \
  root@IP_УДАЛЕННОГО_СЕРВЕРА:/ /путь/к/локальной/папке/backup/
```

**Разбор флагов:**
*   `-aAX` — архивный режим (сохраняет права, симлинки) + сохранение ACL и расширенных атрибутов.
*   `--delete` — удаляет в бэкапе файлы, которых уже нет на сервере (для актуализации).
*   `--numeric-ids` — не пытаться сопоставлять имена пользователей (важно, если на машинах разные пользователи).
*   `--exclude` — **критически важно**: мы исключаем виртуальные папки системы, которые создаются ядром при загрузке, а также временные файлы.

**Как восстановить:**
Загрузиться в новую систему, разбить диски, смонтировать их и запустить rsync в обратную сторону. После этого потребуется поправить `/etc/fstab` и переустановить загрузчик (GRUB).

---

### Способ 3: `tar` (Создание архива)
Если вам нужно просто сложить всю систему в один файл-архив, но `dd` не подходит (слишком большой диск, а данных мало).

**Где выполнять:** На локальном компьютере.

**Команда:**
```bash
ssh root@IP_УДАЛЕННОГО_СЕРВЕРА "tar -cvpzf - --exclude=/proc --exclude=/sys --exclude=/dev --exclude=/tmp --exclude=/run --exclude=/mnt --exclude=/media --exclude=/lost+found /" > debian_full_backup.tar.gz
```

*   `c` — создать.
*   `v` — подробно (вывод файлов).
*   `p` — сохранить права доступа (permissions).
*   `z` — сжать через gzip.
*   `f -` — выводить результат в stdout (чтобы передать через SSH).

**Как восстановить:**
```bash
# Распаковать на смонтированный диск новой системы
tar -xvpzf debian_full_backup.tar.gz -C /mnt/new_system/ --numeric-owner
```

---

### Резюме: что выбрать?

1.  Если нужно **полное зеркало диска** (вместе с пустым местом и разметкой), чтобы восстановить систему одной командой и не думать о настройке GRUB — используйте **Способ 1 (`dd`)**.
2.  Если нужно **сделать копию рабочей системы** для переноса на другой диск/сервер или регулярного бэкапа данных — используйте **Способ 2 (`rsync`)**. Это самый быстрый и безопасный метод для работающей ОС.
