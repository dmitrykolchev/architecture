## Block outbound IPv6 trafic to specific sites (Yandex)

Для блокировки этих подсетей (это диапазоны адресов **Yandex**) на роутере ASUS RT-N66U, нужно добавить 
правила в начало цепочек `FORWARD` (для устройств в локальной сети) и `OUTPUT` (для самого роутера).

**Важное замечание:** Подсеть `2a02:6b8:23::/48` уже входит внутрь `2a02:6b8::/32`. Поэтому технически 
достаточно заблокировать только **`/32`**, и это автоматически заблокирует и вторую подсеть.

Ниже приведена инструкция для создания постоянного скрипта, который сохранится после перезагрузки.

### Шаг 1. Подключение к роутеру
Зайдите на роутер через SSH (как вы делали ранее).

### Шаг 2. Создание скрипта автозагрузки
В прошивке Asuswrt-Merlin 380.xx правила iptables нужно прописывать в `/jffs/scripts/firewall-start`.

Выполните эту команду, чтобы создать или перезаписать файл скрипта (скопируйте блок целиком и вставьте в консоль):

```bash
cat << 'EOF' > /jffs/scripts/firewall-start
#!/bin/sh

# Список подсетей для блокировки
# 2a02:6b8::/32 - Весь Яндекс
# 2a02:6b8:23::/48 - Входит в первую, но добавим для надежности

NET1="2a02:6b8::/32"

# 1. Очистка старых правил (чтобы не дублировались при перезапуске фаервола)
# Скрываем ошибки (2> /dev/null), если правил еще нет
ip6tables -D FORWARD -d $NET1 -j REJECT 2> /dev/null
ip6tables -D FORWARD -d $NET2 -j REJECT 2> /dev/null
ip6tables -D OUTPUT -d $NET1 -j REJECT 2> /dev/null
ip6tables -D OUTPUT -d $NET2 -j REJECT 2> /dev/null

# 2. Блокировка для устройств локальной сети (LAN -> WAN)
# Используем -I (Insert), чтобы правила встали в самый верх
ip6tables -I FORWARD -d $NET1 -j REJECT
ip6tables -I FORWARD -d $NET2 -j REJECT

# 3. Блокировка для самого роутера (Router -> WAN)
ip6tables -I OUTPUT -d $NET1 -j REJECT
ip6tables -I OUTPUT -d $NET2 -j REJECT

EOF
```

### Шаг 3. Установка прав и запуск
Теперь нужно сделать файл исполняемым и запустить его вручную, чтобы применить правила прямо сейчас без перезагрузки роутера.

```bash
chmod a+rx /jffs/scripts/firewall-start
/jffs/scripts/firewall-start
```

### Шаг 4. Проверка
Убедитесь, что правила появились и стоят вверху списка (Chain FORWARD):

```bash
ip6tables -nL FORWARD -v
```

Вы должны увидеть в начале списка:
1.  REJECT ... `2a02:6b8:23::/48`
2.  REJECT ... `2a02:6b8::/32`
3.  ... ваши остальные правила ...

### Почему `REJECT`, а не `DROP`?
В данном случае я использовал `REJECT`, чтобы браузер сразу показывал ошибку соединения, 
а не "висел" пытаясь загрузить страницу. Но для блокировки телеметрии или 
фоновых сервисов лучше подходит `DROP`.
